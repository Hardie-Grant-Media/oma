# Architecture

## Data and access

`api.members`, `clients`, `assignments`, `audits`, `evidence`, `revisions`, `feedback` and `ledger` use RLS. Anonymous roles have no application-table grants. Authenticated users have read grants only. Membership is checked on each query; removing a member blocks an existing JWT. Client assignment scopes all dependent records. Only an active administrator may inspect deletion tombstones.

The API validates the JWT with Supabase Auth, requires confirmed email and active membership, then supplies the actor ID to a service-only command function. The browser cannot invoke privileged commands or worker operations directly. Strategist approval is checked again inside the locked database transaction, with revision compare-and-swap.

Private storage preserves originals. Uploads are proxied after membership, audit-state, byte-size and file-signature checks. HTML is parsed without fetching resources; active nodes are removed. Images retain original colours. CSV rows, columns and unambiguous ISO-date ranges are calculated in code. Staff still verify extracts.

## Jobs

`pgmq` carries durable work. Job state and leases live in Postgres. An advisory-locked claim limits active audit pipelines to three. Each audit has unique stage keys; duplicate submissions do not enqueue another pipeline. Browser closure does not affect jobs.

The hosted dispatcher and worker authenticate with a randomly generated Vault token. A service-only RPC checks its digest; no credential is returned to clients. Local tests may supply `OMA_WORKER_TOKEN` instead. Private tables use RLS with no browser policies and are not exposed through PostgREST.

Stages: extraction → human verification → calibration → assessment → drafting. Requests use pinned `gpt-5.4-2026-03-05`, medium reasoning, strict JSON schemas and no tools. PDF input includes text and page imagery. Source text is explicitly untrusted; instructions come only from the versioned rubric. POV is omitted through a field allowlist.

At most 200,000 counted input tokens and 8,192 output tokens per request. Reservation covers the full standard-price input tier through 272,000 tokens and maximum output. A failed token check cannot submit an assessment. Rates are pinned at US$2.50/M input and US$15/M output; cached input is conservatively charged at the full rate. Missing usage is charged at the reservation ceiling. Do not enable a different model or price tier without updating and testing these bounds.

429 failures may retry up to three attempts. Ambiguous submissions, including network failures and server errors after dispatch, pause without automatic resubmission. Admin recovery attaches a provider response only after its metadata matches the job and audit. A response ID that cannot be recovered requires provider support; the reservation stays held.

## Revisions and deletion

Approvals freeze an HTML artifact generated by the same versioned template used for preview. Later edits clone the draft; the approved artifact remains unchanged. Original AI assessments are never overwritten by reviewer corrections. Export omits internal POV, drift, change reasons and governance fields.

Deletion first sets a tombstone, preventing further assessment results from changing the audit. Cleanup waits for in-flight uploads and uncertain provider submissions, cancels known responses, deletes provider responses/files and storage, then cascades database records. A failed cleanup remains visible to admins and retries. Provider safety logs and backups follow provider retention policies and cannot be erased through this application.

## Operations

Keep `OMA_AI_ENABLED=false` for general use. The user authorised one synthetic canary (`d0e720e7-3655-4483-b542-7277a2507398`) through `OMA_CANARY_AUDIT_ID`, with `OMA_PROVIDER_RETENTION_ACK=true` for stored synthetic Responses only. Reservations are atomically limited to the lower of its audit budget and US$5. Do not extend this exception to client evidence. Dispatch runs every 30 seconds. Monitor Paused, Failed, Uncertain and Deleting jobs, reservations and cost drift. Never blindly reset an uncertain job.

OpenAI documentation states stored Responses have at least 30-day application-state retention, subject to exceptions; background polling is not compatible with zero data retention. The account's project ownership, residency and abuse-monitoring settings remain unverified. No real client evidence has been sent. See [provider data controls](https://developers.openai.com/api/docs/guides/your-data).

Rollback: pause the dispatcher and AI flag, retain the database, then redeploy a known-compatible frontend/functions version. Do not reverse the initial migration against retained client data. Prefer forward fixes and verified backups.

Access, incident and release owners must be named before the pilot.
